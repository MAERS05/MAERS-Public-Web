## 2. 后端核心引擎 (_studio)

路径：`_studio/` (Python 3.10+ 环境，仅在 Admin 模式下运行)

| 文件名 | 描述 |
| :--- | :--- |
| `server.py` | **服务器入口**。按锁文件安装依赖，启动仅回环可达的 `LocalServer`，校验 Host、来源、会话令牌与请求体；按请求及最终路径拒绝内部文件、媒体凭据和 Windows 路径别名。协议见后端开发指南 §4.0。 |
| `requirements.txt` | **依赖锁文件**。固定后端直接与传递依赖版本，启动时核对。 |
| `routes.py` | **路由控制器**。以路由表注册 `/api/*` 与上传/删除接口，统一执行校验、共享锁与状态码映射。 |
| `config.py` | **全局配置**。定义端口号、数据库路径、JSON 快照路径与上传目录常量。 |
| `services/cms.py` | **CMS 服务入口**。统一分发 CMS 请求至节点、标签与封面子服务。 |
| `services/cms_nodes.py` | **节点与文件服务**。直接读写 `*-tree.json` 与 `data/<module>/*.md`，处理增删改移、重命名及异常回滚。 |
| `services/storage.py` | **共享存储边界**。进程内可重入锁、原子文件替换与多文件操作的异常回滚。 |
| `services/cms_store.py` | **CMS 真源适配**。校验 JSON 树并完整重建 SQLite 缓存。 |
| `services/validation.py` | **输入校验器**。对象字段、列表元素、门户卡片、更新日志、标签及树快照结构校验。 |
| `services/contracts.py` | **类型契约**。JSON 载荷、响应、路由函数与 CMS 上下文类型。 |
| `services/errors.py` | **错误边界**。内部异常写入日志，向 API 返回稳定的公开消息。 |
| `services/pages.py` | **页面服务**。独立页面模板、文件名校验及锚定项目路径的创建与删除。 |
| `services/cms_covers.py` | **CMS 私有媒体迁移**。校验文章媒体清单，协调加解锁迁移与失败补偿，最外层事务及回执提交后才清理私有副本。 |
| `services/cms_tags.py` | **标签库服务**。管理 `data/tags/cms-{module}-tag-categories.json` 持久化与查询。 |
| `services/cms_other_tags.py` | **标签运维工具**。处理跨模块的标签重命名、删除与未使用标签清理 (`cleanup_unused_tags`)。 |
| `services/album.py` | **相册分类服务**。管理相册分类增删改查、排序及三级物理目录初始化与销毁。 |
| `services/album_lock.py` | **相册私密化服务**。处理分类加解锁和导出；迁移失败回滚文件与索引、补偿公开桶；共享媒体恢复在调用线程写入，参与外层事务。 |
| `services/photos.py` | **图库图像服务**。以 JSON 为真源、SQLite 为可重建工作索引，处理图片上传、AVIF/WebP 生成、去重、排序、标签及 R2 登记；本地上传三级文件共用唯一 UUID。 |
| `services/space.py` | **空间服务**。管理 `space-tree.json`、`space-collections.json` 及目标 URL 元数据（标题/Favicon）自动抓取。 |
| `services/music.py` | **音乐服务**。管理 `data/music-data.json` 曲目与分类持久化。 |
| `services/music_api.py` | **音乐外部 API**。代理抓取 Bilibili 视频信息、封面与分 P 时长数据。 |
| `services/crypto_keyring.py` | **加密密钥环服务**。持久化保存经主密码加密包裹的数据密钥 (`data/crypto-keyring.json`)。 |
| `services/git_service.py` | **Git 自动化服务**。提供本地仓库状态检查 (`get_git_status`) 与一键提交推送 (`commit_and_push`，内置推送前只读契约与规范守卫门禁自检，即测试套件 01~04 与 09)。 |
| `services/janitor.py` | **垃圾数据清理服务**。扫描全站 `.md`/`.html`/`.json`/`.js` 引用，清理 `photos/` 下未引用孤儿图片/附件、清理孤儿 `.md` 文件并修复数据库幽灵记录。 |
| `tests/run_tests.py` | **测试入口**。命令行运行器（`--fast` 仅只读套件与规范守卫、`-k` 按名称过滤、`-x` 首错即停、`--debt` 查看技术债、`--shrink-baseline` 收缩基线）与推送前门禁 `run_pre_push_check()`。 |
| `tests/__init__.py` | **测试套件注册表**。登记测试套件并标记是否只读，按需懒加载（门禁不加载后端服务与 Pillow）。 |
| `tests/standards.py` | **代码规范扫描器**。定义与开发规范一一对应的扫描规则，涵盖文件命名、目录结构、JS 关键约束、Python 日志格式与版本号递增。 |
| `tests/standards_baseline.json` | **规范技术债台账**。棘轮基线，记录历史未清零项，只减不增。 |
| `tests/helpers.py` | **测试共享工具**。页面清单、JS 文件枚举、import 解析、ES6 导出符号分析（委托 Node / Acorn）。 |
| `tests/sandbox.py` | **沙盒夹具**。内存级 R2 客户端 `MockS3Client` 与临时目录隔离的 `SandboxTestCase`。 |
| `tests/js_analysis.py` | **语法桥**。批量调用 Acorn，缓存 JS 调用、导入与导出分析。 |
| `tests/browser_server.py` | **浏览器测试后端**。真实 HTTP/路由配合临时数据，独立于正常启动流程。 |
| `tooling/` | **开发工具**。固定 Node 依赖、Playwright 配置与 E2E、Acorn 桥和 Vditor 原始基准及可读补丁，详见开发工具说明。 |
| `tools/bump_versions.py` | **版本准备**。按工作区或暂存区改动递增缓存分组，保护未暂存内容。 |
| `tools/check_push.py` | **推送门禁**。校验推送提交与工作区一致后执行完整测试。 |
| `tests/node_runtime.py` | **Node 运行时夹具**。可组合的浏览器环境 mock；未安装 Node.js 时明确失败。 |
| `tests/test_NN_*.py` | **测试套件**。01~04 只读契约，05~07 沙盒回归，08 Node.js 运行时实测，09 代码规范与基线守卫，10 真实回环 HTTP 安全与鉴权后沙盒写入，11 真源优先、缓存重建、并发读写与异常回滚，12 AST、版本暂存隔离与错误边界。 |
| `tools/build_desktop_app.py` | **桌面启动器构建工具**。调用系统 `.NET csc.exe` 编译生成无黑框原生启动器 `Maersy.exe`。 |
| `tools/upload_to_r2.py` | **R2 云同步工具**。基于 `boto3` 将本地新增或变更的图片、封面与附件增量上传至 Cloudflare R2。 |
| `tools/r2_config.json` | **R2 配置文件**。存储 Cloudflare R2 端点、凭据与公开访问域名配置。 |

### 5.1 数据规模建议 (Recommended Limits)
为确保纯静态访客端在各类设备上的极致流畅度，建议遵循以下规模参考：

| 数据类型 | 推荐上限 | 说明 |
| :--- | :--- | :--- |
| **JSON 索引文件** (`*-tree.json`) | **< 500KB** | 约合 2000 个节点。因正文已分离为独立 `.md` 文件，索引体积增长极慢。 |
| **图库数据** (`photos-data.json`) | **< 3MB** | 约合 5000 张图片元数据。 |
| **音乐数据** (`music-data.json`) | **< 1MB** | 约合 1000 首单曲元数据。 |
| **Markdown 单文件** | **< 100KB** | 纯文本约 3~5 万字，配合目录大纲可保持流畅渲染。 |
| **标签分类** | **< 50 个/每模块** | 保持抽屉筛选器良好的视觉密度与可读性。 |

- `_studio/services/cms_covers.py`：统一封面与正文插图迁移；缺失清单及跨文章共享引用阻止加锁；失败时补偿公开原图删除，保留私有副本供恢复或重试。
- `_studio/services/photos.py`：媒体文件名与真实路径边界校验；图片删除失败时还原文件、JSON，并重建缓存。
- `_studio/services/storage.py`：多文件异常回滚、回滚后补偿外部副作用、成功提交后启动外部任务、中继操作持久化回执。
- `data/.relay-receipts.json`：仅本机保存的中继操作回执，记录来源/操作内容指纹及结果，不含正文，不纳入 Git；清除该文件会失去历史重试去重记录。

文章移除封面或删除节点时仅解除引用，图片留待垃圾清理回收。`photos.py` 的云端登记仅在原图下载和衍生图生成全部成功后发布索引，失败回滚并允许中继重试；`janitor.py` 对索引中的真实文件键只统一分隔符，仅对正文链接及明确的远程地址复用媒体 URL 解码规则，保留文件名中的字面 `#` 和百分号。

加密设置入口由 `encrypt/admin-lock.module.js` 统一挂载，仅后台管理首页展示；本地可操作，线上后台首页置灰。各模块的卡片加解密与批量取消加密操作独立于设置入口。`encrypt/crypto-settings.module.js` 拒绝在线上打开设置或同步 Worker 令牌。
`ui/secret-key.svg` 用于加密设置入口及弹窗，`ui/encryption.svg` 用于加锁按钮及锁定占位，`ui/decryption.svg` 为同风格开锁图标，用于后台“取消对外加密”按钮；共享图标渲染位于 `encrypt/lock-dialog.module.js`，三项资源均纳入离线清单。

顶栏由 `sync/sync-manager.module.js` 提供统一的“本地模式 / 云端模式”入口，Git 提交位于设置面板内。存在改动时显示“本地待Git(文件数)”或“云端待Git(草稿数)”；云端待合并数量与本地 Git 文件数分别统计。
设置面板的“Git 一键提交(数量)”与顶栏使用相同计数。“验证主密码”建立本机内存管理状态，加密内容在后台照常显示并可编辑，保存时自动重新加密；“退出私密管理”清除管理密钥，不改变主密码、密钥环或文件。内容页统一称“取消加密 / 取消全部加密”，表示恢复公开；相册还会迁回公开存储。备份面板按本机备份、清理回收区分区展示，长列表在面板内滚动。
左下角密钥、取消全部加密和展开箭头共用一个圆角外框。有加密记录时，箭头在展开、收起两种状态均保持蓝色背景并位于整个控件最右端；取消加密区域通过宽度、透明度过渡横向展开或收回，收起时不可点击或键盘聚焦。没有加密记录时，仅保留密钥入口。
