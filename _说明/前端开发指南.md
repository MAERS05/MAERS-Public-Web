## 1. 模块化规范 (ES6 Modules)

本项目全面采用浏览器原生 ES6 模块标准（无打包构建工具）。

### 1.1 文件结构与命名
- **命名**: 小写 kebab-case（STD-FILE-01）。
- **后缀**: ES6 模块**必须**以 `.module.js` 结尾（STD-FILE-02）。经典脚本例外登记在 `standards.py` 的 `NON_MODULE_JS_ALLOWLIST`：`custom/config.js`、`shared/flash-guard.js`、`custom/index/viewer/site-guide.js`、`custom/zmobile adaptation/mobile-literature.js`、`custom/zmobile adaptation/mobile-photos.js`、`custom/zmobile localization/offline-download.js`、`data-manage/sync/cloudflare-worker-sync.js`（Worker 源码）。另有根目录的 Service Worker `maers-version-controller.js`。
- **文件头**: 每个 JS 文件以 `/** */` 中文职责注释开头（STD-JS-05）。
- **位置**（STD-FILE-04）:
  - 业务逻辑放在 `custom/<module>/` 下。模块根部只放 `main.module.js` / `admin-main.module.js` / `*-adapter.module.js`，其余文件严格区分 `viewer/`（访客端）与 `admin/`（管理端）。
  - 跨模块共享 UI 基础设施（主题、布局、工具、Toast）放在 `shared/`。
  - 管理中台与数据层放在 `data-manage/`：
    - 根部：`api-client.module.js`（后端请求）、`data-provider.module.js`（数据读取）；
    - `admin/`：保存条、弹窗、批量管理、按钮渲染；
    - `encrypt/`：加密、密钥环、私密媒体、管理锁、秘密解锁、加密设置；
    - `sync/`：`sync-manager` 门面、Cloudflare 中继、GitHub 同步、Git 提交、Worker 源码。

### 1.2 引用方式 (Import/Export)
- **显式依赖**: 使用 `import` 语句通过相对路径显式声明依赖项。
- **严控全局命名空间**: 业务逻辑模块严禁向 `window` 挂载全局变量。
  - **基础设施豁免**: 仅允许 `window.MAERS.Toast`、`window.MAERS.Theme`、`window.MAERS.ModuleConfig`、`window.MAERS.Config` 四个横切关注点服务驻留 `window.MAERS`（STD-ARCH-01，test_04 强制）。

```javascript
/* ✅ 推荐写法 */
import { Utils } from '../../shared/utils.module.js';
import { createGridItem } from './render/cms-render-grid.module.js';

export function init() { ... }
```

### 1.3 HTML 入口
每个 HTML 页面仅需引入对应的主入口模块：

```html
<!-- ✅ 正确 -->
<script type="module" src="custom/cms/main.module.js"></script>
```

## 2. 关键渲染路径 (Critical Rendering Path)

为了提供极致的首屏体验和零闪烁的深浅色主题切换，项目采用了严格的加载时序。

### 2.1 Flash Guard (防闪烁脚本)
`shared/flash-guard.js` 是项目中最关键的同步阻塞脚本（详见 [架构决策记录 - ADR-006](架构决策记录.md#adr-006-关键路径同步渲染-flash-guard)）：
- **同步执行**: 必须作为普通脚本 (`<script src="shared/flash-guard.js"></script>`) 放在 `<head>` 最顶部，**禁止**添加 `type="module"`、`defer` 或 `async`。
- **核心职责**:
  1. 读取 `LocalStorage` 主题偏好，立即为 `<html>` 注入 `light-mode` 类与初始背景底色，注入 `.js-loading` 遮罩防止 FOUC。
  2. 恢复全局视口缩放状态与 Favicon。
  3. 动态注入 PWA `manifest.json`、Service Worker (`maers-version-controller.js`) 及全站离线下载脚本 (`offline-download.js`)。

### 2.2 标准 `<head>` 资源加载顺序
1. `<script src="custom/config.js"></script>` (全局环境配置)
2. `<script src="shared/flash-guard.js"></script>` (阻塞式防闪烁与主题初始化)
3. `<link rel="stylesheet" ...>` (全局样式表：`theme.css`, `components.css`, `style.css`, `responsive.css`)
4. `<script type="module" ...>` (业务入口模块)

### 2.3 首页提前显示
公开首页通过 `data-early-render="home"` 标记，在同步主题已恢复、HTML 解析到 `interactive` 时揭示正文，不等待整条 ES 模块依赖链。其他页面仍等待 `DOMContentLoaded` 与页面守卫结束，禁止把该标记复制到可加锁的模块页面。

首页在 `<head>` 优先预加载首屏及嵌套移动样式、`index-cards.json`，用 `modulepreload` 并行发现入口依赖；不参与首帧主题判定的配置和引导脚本使用 `defer`，离线面板在 `load` 后加载。首页与空间导航通过 `spatial-nav.module.js` 的 `getNavData()` 共用一次页面内请求，各自取得独立卡片副本，失败不缓存。预加载清单需随首页静态依赖调整。

## 3. 数据交互 (Data Fetching)

### 3.1 静态快照 + 按需加载
- **Static Tree**: 访客端初始化时异步请求 `data/*-tree.json`（仅含目录层级与元数据，体积轻量）。
- **Lazy Content**: 用户点击文章节点时，根据节点的 `content` 字段路径（如 `data/notes/xxx.md`）按需 `fetch` 物理 Markdown 正文并交由本地化 `Vditor.preview` 渲染。
- **Tag Categories**: 标签分类配置独立存储于 `data/tags/<scope>-tag-categories.json`（`cms-<module>`、`photos-<category>`、`space` 等，见 STD-DATA-02）。
- **管理端请求**: 统一经 `data-manage/api-client.module.js` 发起，API 地址读取 `window.MAERS.Config.API_BASE`，禁止硬编码 `localhost:端口`（STD-JS-07）。

## 4. CSS 架构与移动端规范

### 4.1 四层样式架构
1. **Base (`cms-base.css`, `style.css`)**: 核心网格、弹性布局与排版骨架。
2. **Theme (`theme.css`, `cms-theme-default.css`)**: CSS 变量色彩令牌、深浅色阴影与毛玻璃装饰。
3. **Module (`literature.css`, `games.css`, `videos.css` 等)**: 特定模块的定制样式。
4. **Mobile (`custom/zmobile adaptation/`)**: 物理隔离的移动端响应式补丁。

### 4.2 变量优先与浅色模式适配
- 优先使用 `static-style/theme.css` 中的 CSS 变量（如 `var(--bg-base)`、`var(--text-main)`、`var(--card-bg)`）。
- 若编写独立浮动组件（如离线下载按钮 `.od-btn`、自定义抽屉等），**必须**同步检查并编写 `html.light-mode` 下的背景、边框与图标颜色规则，严禁出现浅色模式下“白底白图标”不可见的问题。

### 4.3 移动端适配策略 (Mobile Adaptation)
- **物理隔离**: 所有针对移动端（`max-width: 1024px` / `768px`）的 `@media` 查询**严禁**散落在主 CSS 文件中，必须统一存放在 `custom/zmobile adaptation/` 目录下（如 `mobile-global.css`、`mobile-cms.css`、`mobile-photos.css`、`mobile-music.css`、`mobile-games.css`、`mobile-record.css` 等）。
- **加载方式**: 在对应主 CSS 文件的**最顶部**通过 `@import` 引入：
  ```css
  @import "../../zmobile adaptation/mobile-music.css";
  ```
- **权重管理**: 移动端样式选择器统一添加 `body` 前缀（如 `body .example-container`）以自然提升优先级，减少 `!important` 滥用。
- **极致性能降级**: 移动端禁用高开销的 `backdrop-filter`、`#theme-mask` 全屏遮罩与大面积渐变过渡（`transition: none !important`），确保触控零延迟。

## 5. 编码风格 (Coding Style)

- **事件驱动**: 避免使用 `setInterval` 轮询状态，优先使用发布/订阅 (`on/emit`) 或事件回调驱动 UI 更新。
- **异步编程**: 统一使用 `async/await` 处理异步流。
- **代码洁净度**: 严禁保留废弃的“僵尸代码”或无用注释；重构功能时直接删除旧逻辑。
- **中文注释**: 所有新增或修改的代码注释统一使用清晰、准确的中文说明设计意图。

## 6. 安全与端到端加密规范 (Security & E2EE)

### 6.1 XSS 防护 (Cross-Site Scripting)
- 渲染动态文本时优先使用 `textContent`。
- 若必须使用 `innerHTML`（如搜索关键词高亮或复杂卡片组装），**必须**先通过 `Utils.escapeHtml()` 转义所有动态字段。
- **受控例外**: `cms-render-nav.module.js` 中的 `renderPageTitle` 允许渲染来自内部可信配置（如 `Music & Videos` 跨模块切换标题）的 HTML 片段。

### 6.2 端到端加密 (Web Crypto E2EE)
- 私密文章与私密相册的加解密基于 `data-manage/encrypt/crypto.module.js`（浏览器原生 `SubtleCrypto`：`PBKDF2` + `AES-GCM`）与 `data-manage/encrypt/keyring.module.js` 完成。
- 主密码仅在浏览器解包数据密钥。按 STD-DATA-04，本地后台由 `admin-session.module.js` 经鉴权回环请求建立内存管理状态；主密码不发送，本机服务不保存明文密钥文件。线上仍在浏览器解密，不能连接本机管理接口。
- 后台读取私密正文与数据使用 `localFetch`，由服务提供内存管理视图；发布的 JSON 继续保留密文。正文编辑保留逻辑媒体键，只在预览时转换成本机私密媒体地址，禁止把转换后的地址或明文工作内容写入云端队列。

### 6.3 门面与架构边界 (Facades)
业务模块（`custom/`）只能通过高内聚门面使用加密与同步能力，由 test_04 架构边界守卫强制：

| 能力 | 门面 | 禁止 |
| :--- | :--- | :--- |
| 私密媒体 / 节点加解锁 | `data-manage/encrypt/private-media.module.js`、`admin-lock.module.js`、`secret-unlock.module.js` | 直接调用 `crypto.subtle`、导入 `keyring.module.js`、硬编码 `enc:` 前缀（STD-ARCH-02） |
| 云同步 | `data-manage/sync/sync-manager.module.js` | 直接导入 `cloudflare-relay` / `github-sync` 等底层实现（STD-ARCH-03） |

## 7. SVG 图标与昼夜主题适配

针对项目中使用的单色 SVG 图标（`ui/*.svg`），严禁在 SVG 源码内硬编码多套颜色，统一通过 CSS `filter` 动态适配昼夜模式：

```css
/* 1. 默认状态 (深色模式): 将纯黑 SVG 反转为白色 */
.container img[src*="icon-name"] {
    filter: invert(1);
}

/* 2. 浅色模式状态: 还原原始深色 */
html.light-mode .container img[src*="icon-name"] {
    filter: none;
}
```
- 必须限定在具体容器选择器内并通过 `src*="..."` 精准匹配图标文件名，严禁对全局 `img` 标签应用 `invert`。

## 8. 适配器模式与权限隔离 (Adapter & Permissions)

### 8.1 跨模块复用 (CMS Adapter)
需要复用 CMS 标签抽屉与筛选器（支持 `AND` / `OR` / `DEL` 三种模式）的非 CMS 模块，统一通过 `custom/cms/cms-adapter.module.js` 及其模块特化适配器接入：
- **Photos**: `setupPhotosAdapter` (`custom/photos/admin/photos-cms-adapter.module.js`)
- **Space**: `setupSpaceAdapter` (`custom/space/admin/space-cms-adapter.module.js`)

### 8.2 权限双轨制 (Dual Permission)
在访客端（Viewer）初始化适配器时，**必须**显式锁定 `IS_ADMIN: false`，防止标签编辑、右键菜单等管理 UI 泄露到前台：

```javascript
// ✅ 访客端 Viewer 正确写法
const adapter = setupPhotosAdapter(callback, controller, {
    initialState: { IS_ADMIN: false }
});
```

## 9. 图像处理与懒加载 (Image Handling)

### 9.1 原生懒加载 (Native Lazy Loading)
- 所有列表图片与缩略图统一使用语义化 `<img loading="lazy">` 标签配合 `object-fit: cover`，严禁使用 `div.background-image` 或手写 `IntersectionObserver`。

### 9.2 多级图像规格选用
- **列表/网格展示**: 必须加载 `400px WebP` 缩略图 (`photos/thumbnails/...`)。
- **灯箱高清预览**: 加载 `1600px AVIF` 预览图 (`photos/previews/...`)。
- **原图下载**: 仅在用户点击下载原图时请求 `photos/images/...` 原始文件。
- **海报纵横比**: `Literature`、`Games`、`Videos` 三大模块统一采用 **2:3** 竖屏海报比例（基准尺寸 `140px × 210px`）。

### 9.3 封面路径以图片索引为准
书架、游戏抽取及 CMS 海报网格通过 `DataProvider.loadCoverIndex()` 读取 `photos-data.json`，由 `DataProvider.getCoverUrl(node, 'thumb' | 'preview')` 获取真实衍生路径，禁止根据原图文件名或模块分类拼接。公开 CDN 地址按路径匹配索引，真实文件键中的字面百分号不按 URL 再次解码。

显式 `coverThumb` / `coverPreview`（包括私密访问凭证）始终优先；图片尚未登记或索引不可用时使用原图地址。索引请求在页面内复用，管理端重新加载内容时刷新，失败允许重试。展示过程不向文章节点写入衍生字段，避免把临时媒体地址保存进正文数据。

## 10. 缓存版本控制与离线化 (Service Worker & PWA)

### 10.1 三级缓存版本控制 (`maers-version-controller.js`)
Service Worker 拦截同源静态请求并附加 `?maers_ver=...` 参数穿透 CDN 缓存，匹配优先级从高到低为：
1. `VERSION_CONFIG.files`: 单文件精确热修复覆盖。
2. `VERSION_CONFIG.groups`: 按模块目录分组（如 `styles`、`cms`、`shared`、`photos`、`music` 等），日常修改某模块的前端代码后，只需将该分组的 `version` 数字 `+1`。
3. `VERSION_CONFIG.default`: 全站大版本兜底时间戳。

> [!IMPORTANT]
> 修改前端文件后必须递增对应版本键（STD-VER-01）。test_09 会对比上游合并基点，并列出需要递增的键名。

### 10.2 全站离线下载 (`offline-download.js`)
- 新增或删除访客端静态文件（HTML/CSS/JS）时，同步更新 `custom/zmobile localization/offline-download.js` 的 `FRAMEWORK` 数组（STD-VER-02）。test_02 校验清单无死链、无重复，并覆盖全部访客页面。

## 11. CMS 纯阅读器 (Pure Reader)

`custom/cms/viewer/cms-reader.module.js`（v4）是前后台统一的**纯阅读器**，不再创建 `new Vditor` 编辑实例（test_04 `pure_reader_contract` 强制）：

- **渲染内核**: `Vditor.preview`（本地化资产 `plugins/vditor-assets/`），使用其默认 HTML 净化；引擎缺失时通过 `textContent` 显示 Markdown 纯文本，不将 `marked` 输出或原始正文直接插入 `innerHTML`。
- **扩展语法**: `[[双链]]` / `[[目标|显示文字]]` 转换为 `.cms-wikilink`，反向链接由 `viewer/cms-backlinks.module.js` 渲染；支持 GitHub Alerts（`> [!NOTE]` 等）提示卡。
- **内链拦截**: `_interceptMdLinks` 拦截 `.md` 相对链接，在页内无刷新跳转。
- **外部编辑**: 管理端通过 `POST /api/cms/node?action=open_external` 唤起本地 Typora / Obsidian，窗口回焦时热刷新并保持滚动位置。
- **辅助能力**: 动态大纲（H1–H6）、源码抽屉、阅读滚动同步（`viewer/cms-scroll-sync.module.js`）。

阅读器入口位于 `viewer/`，由 `Reader` / `initReader` 显式注入。正文处理、目录与生命周期、图表、滚动同步分属独立模块；已移除旧富文本实例兼容字段。

第三方脚本定制必须编辑可读补丁并重建，禁止直接修改生成产物。补丁构建、浏览器测试和提交版本工具见[开发工具说明](../_studio/tooling/README.md)。
