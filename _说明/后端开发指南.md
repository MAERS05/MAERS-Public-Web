# MAERS 后端开发指南 (Python)

本文档解析 MAERS 的后端架构，即 `_studio/` 下的核心引擎。强制规则见 [开发规范 §6 / §7](开发规范.md#6-python-后端-py)。

**定位**：后端只在**管理模式**下运行（通常由根目录 `Maersy.exe` 静默拉起），为管理门户与阅读器提供以下能力：物理文件读写、SQLite 缓存重建、图像多级处理、加密密钥环持久化、垃圾数据清理，以及 Git / R2 同步。访客端是纯静态站点，不依赖后端。

## 1. 架构概览

运行环境为 **Python 3.10+**。后端基于 **Python 原生 `http.server` (`ThreadingHTTPServer`)**，不使用 Flask / Django，分为四层：

1. **Bootstrap & Server (`server.py`)**
   - **依赖自检 (`ensure_dependencies`)**：在导入业务模块前，按 `_studio/requirements.txt` 核对直接及传递依赖的固定版本；缺失或版本不符时用当前解释器执行 `pip install -r`，安装失败则停止启动。导入 `server` 供测试使用时不安装依赖或改变工作目录。
   - **多线程并发**：`LocalServer` 继承 `ThreadingHTTPServer`，仅绑定 `127.0.0.1`；同时处理静态资源与 API 请求。
   - **启动对齐**：启动时同步相册数据，并从 JSON 快照对齐 CMS 数据。
2. **Route (`routes.py`)**：`ROUTES` 路由表用装饰器注册接口、校验器与锁策略；`dispatch_get` / `dispatch_post` 统一执行校验、分发及状态码映射。
3. **Service (`services/`)**：业务逻辑，包括数据库索引、物理文件同步、图像转换、密钥环、垃圾清理与 Git。
4. **Data (`data/` 与 `photos/`)**
   - **Cache**：SQLite（`data/cms.db`、`data/gallery.db`），可由 JSON 重建，不纳入 Git。
   - **Content**：Markdown 正文（`data/<module>/*.md`）与三级图像（`photos/`）。
   - **Snapshot**：供访客端消费的 JSON 快照（`data/*-tree.json`、`data/photos-data.json` 等）。

## 3. 核心服务 (Services \& Tools)

### 3.1 CMS 服务集群 (`cms*.py`)
负责 `notes`、`literature`、`record`、`games`、`videos` 五个内容模块：

- **节点与物理文件同步 (`cms_nodes.py`)**：节点层级、标题、标签与正文路径以 `data/<module>-tree.json` 为准，正文存储在 `data/<module>/*.md`。节点操作直接读写 JSON 与正文；`cms_store.py` 单向重建 SQLite 缓存。一致性边界见 §5。
  删除文章或移除封面仅解除图片引用，不立即删除图片文件。附件由垃圾清理统一判断全部引用后回收，避免去重图片被多个节点复用时误删。
- **外部编辑器 (`open_external`)**：管理端阅读器请求后，后端用系统默认程序（Typora / Obsidian 等）打开对应 `.md`。前端在窗口回焦时自动热刷新。
- **加解锁与私密图片 (`cms_covers.py`)**：
  - 密文同时包含正文及 `mediaRows` 图片行；`covers` 参数列出封面和正文插图对应的原图键。加锁前核对真实正文引用，并将三个尺寸迁入私有桶校验；遗漏图片或跨文章共享图片时拒绝加锁。
  - 解密阅读将插图转换为私有桶令牌地址；永久解锁恢复图片行及文件，删除加密节点时一并清理插图。
  - `mediaVersion` 标记已完成媒体清单处理的节点。存在未标记的历史密文时，清理器保守保留本地图片；解锁后重新加锁可完成迁移。包含历史密文子节点的父节点继续保留此保护。
  - 解锁失败时回滚图片迁移。
  - 加锁的正文、树 JSON 与图片索引处于同一异常回滚边界。公开桶删除或外层中继回执保存失败时恢复文章与本地文件，并从私有副本补回已尝试删除的公开原图。若公开桶持续不可用，保留私有副本，下一次加锁可复用副本继续执行。
  - 删除加密节点时可以携带 `purge_private` 清理私有桶对象。
- **标签系统 (`cms_tags.py` 与 `cms_other_tags.py`)**：标签分类独立存储在 `data/tags/*-tag-categories.json`（命名见 [ADR-032](架构决策记录.md#adr-032-标签配置命名规范-tag-configuration-naming-convention)），支持跨数据源（CMS / Photos / Space）的重命名、删除与未引用标签清理。

### 3.2 相册与图库 (`album.py`、`album_lock.py`、`photos.py`)

媒体登记、上传、删除及私有迁移使用 `photos.media_path()` 校验真实路径，仅允许 `photos/{images,thumbnails,previews}/<分类>/<文件名>`。图片删除发生运行时异常时恢复原文件与 JSON，数据库缓存从真源重建；远端 R2 删除在文件事务成功后才启动。

本地上传以同一个 UUID 标识原图、缩略图及预览图，文件名保留拍摄时间前缀；同一时间上传不同扩展名不会共用衍生文件编号。重复文件仍按原有哈希规则去重，缺失原图修复沿用已有记录。

手机直传的 Worker 同样采用时间前缀加 UUID 的原图名；更新 `data-manage/sync/cloudflare-worker-sync.js` 后需单独重新部署 Worker。登记接口保留已上传的原图键，用完整相对路径（含扩展名）的 SHA-256 摘要作为衍生编号，因此旧 Worker 上传的同名 `.png` / `.jpg` 也不会再共用缩略图或预览图。重复登记使用同一编号和图库记录，避免重试生成额外文件；本地后端代码更新后需重启管理端。

前端封面展示从 `photos-data.json` 读取实际的 `thumb` / `preview`，不再假设衍生图与原图同名；书架、游戏抽取、文学及视频网格共用解析入口，详见[前端开发指南 §9.3](前端开发指南.md#93-封面路径以图片索引为准)。

相册加锁必须成功删除公开桶原图及本地三级文件后才能发布成功；公开删除或配置发布失败，回滚本地文件、标签、JSON 与图库缓存，并尝试从保留的私有副本补偿公开原图。CMS 和相册解锁在迁回前登记回滚补偿；本地写入在事务所在的调用线程执行，远端上传响应丢失也会撤回已尝试公开的原图。私有副本仅在最外层事务（包括中继成功回执）提交后清理。远端补偿持续失败时记录错误并保留私有副本，允许后续重试；不承诺云端与本地的跨系统原子提交。

手机 R2 图片登记使用桌面启动环境可解析的 `tools.upload_to_r2`，先下载原图并成功生成缩略图、预览图，再发布索引。CDN 失败后尝试配置的公开桶；取回或衍生图生成失败返回错误，回滚本地写入且不保存成功回执，中继队列保留该操作供重试。

路径处理区分真源中的文件键与 URL 引用：CMS 正文路径、图库三级路径及配置中的本地图片键只统一分隔符，保留字面的 `#` 和 `%20`。从正文提取的 URL 和明确的远程图片地址才去除参数、片段，解码一次并规范化路径；垃圾清理与加锁校验复用这部分 URL 解析规则。

CMS 节点与 R2 登记请求可以携带 `_relay: { source, key }`，用于同步重试。`data/.relay-receipts.json` 保存内容指纹与结果，刷新页面后仍可去重；相同键对应不同操作返回 409。回执不含正文、不纳入 Git，不应在仍有未确认队列时删除。

- **分类管理 (`album.py`)**：相册分类的增删改排，联动管理 `photos/images/{cat}`、`photos/previews/{cat}`、`photos/thumbnails/{cat}` 三级目录。
- **图像流水线 (`photos.py`)**：上传时生成三种规格：
  - `Origin`：原图，存于 `photos/images/`。
  - `Preview`：1600px AVIF，存于 `photos/previews/`。
  - `Thumbnail`：400px WebP，存于 `photos/thumbnails/`。

  元数据以 `data/photos-data.json` 为准；每次图库业务操作先重建 `gallery.db`，用临时索引完成去重、排序与更新，再原子保存 JSON。`handle_register_r2` 将移动端直传到 R2 的图片登记到这一流程。
- **分类私密化 (`album_lock.py`)**：以后台任务执行加密导出与私有桶迁移，进度通过 `/api/album/job` 查询，失败时回滚。

### 3.3 空间与音乐 (`space.py`、`music.py`、`music_api.py`)
- **Space**：维护 `data/space-tree.json` 与收藏集，`fetch_url_metadata` 抓取目标网页的标题、描述与图标。
- **Music**：维护 `data/music-data.json`，通过 `music_api.py` 按 BV 号拉取标题、封面与分 P 列表。

### 3.4 运维、安全与工具链
- **Janitor (`janitor.py`)**：扫描全站 `.md` / `.html` / `.json` / `.js` 与两个数据库，清理以下内容，然后重新生成 `photos-data.json`：
  - 未被引用的孤儿图片与附件；
  - 未注册的孤儿 `.md`；
  - `gallery.db` 中的幽灵记录。
- **Git (`git_service.py`)**：使用 `status --porcelain -z` 保留中文与特殊文件名；封装 `add .`、`commit` 和 `push origin HEAD`。提交前执行 `run_pre_push_check()` 只读门禁，推送仍执行 Git hook 完整回归；通过只读进度接口反馈阶段，超时结束 Git 子进程树。
- **密钥环 (`crypto_keyring.py`)**：只接收前端用主密钥包裹后的密钥槽，校验结构后原子写入 `data/crypto-keyring.json`，并拒绝覆盖式降级。
- **桌面启动器构建 (`tools/build_desktop_app.py`)**：用系统 `.NET Framework csc.exe` 将内置 C# 源码编译为 `Maersy.exe`。

## 4. API 路由规范

所有接口定义在 [`routes.py`](../_studio/routes.py)。CMS 节点类接口由 [`cms.handle_request`](../_studio/services/cms.py) 按 `NODE_ACTIONS` 动作表二级分发；字段类型、列表元素与快照结构由 `services/validation.py` 校验。

### 4.0 本地会话与请求校验

本地管理页面从 `http://localhost:8001` 或 `http://127.0.0.1:8001` 打开。端口和请求体上限定义在 `config.py`；`file://`、其他端口及线上网站不在来源白名单内。

- 所有请求都检查 `Host`，只接受当前端口的 `localhost` / `127.0.0.1`，防止 DNS 重绑定。有 `Origin` 时必须匹配上述两个本地来源；不再返回通配 CORS。
- 静态文件边界同时检查请求路径和解析后的最终文件路径：拒绝 `_studio/`、隐藏文件、媒体凭据、站点目录外的链接目标，以及 Windows 大小写、尾点/空格和数据流别名；同源 `GET` / `HEAD` 也不能下载这些文件。
- `GET /api/session` 由 `server.py` 处理，要求 `X-MAERS-Client: studio`，返回 `{ "token": "…" }`。自定义头使跨源读取先经过预检，外部来源不能读取令牌。响应禁止缓存；令牌每次启动重新生成，只保存在服务与页面内存中。
- 全部 `POST`（包括 `/upload`、`/delete`、`/reorder`）要求可信 `Origin` 和 `X-MAERS-Token`。前端显式导入 `data-manage/api-client.module.js` 的 `localFetch` 或 `api`，自动获取和携带令牌。外部云服务请求继续使用各自的鉴权。
- 普通写入必须为 `application/json`（可带 charset），上限 **16 MiB**。`/upload` 接收原始二进制，上限 **64 MiB**。必须提供唯一、有效的 `Content-Length`，不支持分块传输；上限在读取 body 前检查。
- 非法来源 / 令牌返回 `403`，错误类型返回 `415`，缺少长度返回 `411`，超限返回 `413`，无效长度 / JSON / 截断 body 返回 `400`，读取超时返回 `408`。被拒绝的请求不会进入业务分发。
- 服务重启导致令牌失效时返回 `403` 和 `code: invalid_session`；客户端重新获取后只重试一次。其他错误及网络失败不自动重放写操作。

这是本机浏览器请求的隔离措施；会话令牌不承担多用户身份认证。命令行集成也需要先获取令牌，再带可信 `Origin` 和令牌调用写接口。

### 4.6 状态码约定

本地后台持有管理令牌的 GET 可读取私密内存视图；未带令牌的静态 GET/API 仍返回发布密文。私密正文虚拟路径不落盘，私密视图和媒体响应禁止缓存。`/upload` 可携带 `module`、`node_id`、`cover=1`，服务以目标文章真实加密状态决定公私存储；加密相册同样直接私有上传。所有业务写入在存在加密内容但尚未验证时返回 `403 private_admin_required`，不能回退为公开写入。密钥、正文与媒体处理约束见 STD-DATA-04 和[数据保障与存储迁移](数据保障与存储迁移.md#后台管理与对外加密)。

| 状态码 | 场景 |
| :--- | :--- |
| `200` | 成功。body 为业务结果，或 `{"status": "success"}` |
| `400` | 参数缺失 / 非法、未知 `action`、业务校验失败（`ValueError`） |
| `404` | 资源不存在，或 POST 访问未知接口（`{"error": "API not found"}`）。非 API 的 GET 未命中时交给静态文件处理，未知 `/api/*` 返回 JSON 错误 |
| `405` | 方法不允许（如 GET `/api/space/save_tree`） |
| `500` | 未预期的内部异常（body 含 `error`） |

## 5. 数据流向

### 真源与缓存
- CMS 元数据以 `data/<module>-tree.json` 为准，正文以 `data/<module>/*.md` 为准；图库元数据以 `data/photos-data.json` 为准。其他模块的 JSON 配置同样是持久化真源。
- `data/cms.db` 与 `data/gallery.db` 是可丢弃缓存，不纳入 Git；启动时从 JSON 完整重建。删除或损坏缓存不会反向修改 JSON。恢复、备份与 Git 合并应以 JSON、Markdown 和媒体文件为对象。
- CMS 每次操作读取最新 JSON；图库业务操作先从 JSON 重建工作索引，再将结果原子保存回 JSON。CMS 的缓存更新失败只记录待重建状态，不撤销已经成功保存的真源。
- JSON 文件不存在时按空模块初始化；文件存在但 JSON 无法解析时明确报错，禁止把解析错误当成空数据继续改写。清理服务在引用扫描失败时中止删除。

### 写入流程（管理端）
1. 前端通过统一客户端提交；HTTP 层校验会话及请求体，路由层按接口校验结构。非法 JSON 返回 `400`，不进入业务层。
2. 服务端请求与相册后台迁移共享 `storage.LOCK`，锁覆盖完整的读取、修改和保存。任务进度查询不取此锁，迁移期间仍可读取进度。
3. JSON 与 Markdown 通过同目录临时文件、`flush/fsync` 与 `os.replace` 原子替换，避免半截文件。CMS 节点及跨文件标签操作使用 `storage.transaction()`，异常时尝试恢复本次改动前的文件内容。
4. CMS 新正文先写入，再发布 JSON；删除先发布 JSON，再移除旧正文。缓存只由真源重建。响应成功后前端刷新视图。

锁的范围是单个服务进程，不能协调外部编辑器、手动 Git 操作或第二个服务进程。跨文件回滚用于处理运行期异常，并非断电事务；持续磁盘故障也可能妨碍恢复。R2 迁移仍遵循各服务的复制、验证、清理流程，不属于本地文件回滚事务。

### 配置与启动目录
`_studio/config.py` 是端口的唯一定义。桌面启动器调用 `config.py --port`，前端 API 地址取当前页面的 origin。修改端口后重启启动器即可；服务端路径锚定项目目录，不调用 `os.chdir`。`file://` 页面无法执行后台写入，请通过启动器打开管理页面。

### 读取流程（访客端）
访客端先请求轻量的 `data/*-tree.json` 渲染目录，点击卡片后再按需 `fetch` `.md` 正文或 WebP / AVIF 图像。加密内容在浏览器内解密。

## 7. 新增接口的标准步骤

1. **服务层**：在 `services/<domain>.py` 中实现业务函数（模块 docstring、双语日志、具体异常类型）。超过 700 行时按子职责拆分。
2. **路由层**：在 `dispatch_get` / `dispatch_post` 中解析参数并映射状态码（§4.6），路由层不写业务逻辑。
3. **依赖**：若引入第三方库，同步加入 `server.py` 的 `ensure_dependencies()` 列表。
4. **安全**：用户可控的文件名必须拒绝 `..`、`/`、`\`；关键 JSON 采用“临时文件 + `os.replace`”原子写入。
5. **测试**：在沙盒套件（05–07）中补充用例，覆盖成功路径与 `400` / `404` 分支。
6. **文档**：更新本文 §4 的接口表与 [文件功能说明](文件功能说明.md)。

## 9. 管理操作手册 (Management Operations Manual)

### 9.1 启动与退出
- **一键启动**：双击根目录或桌面上的 **`Maersy.exe`**。启动器在后台无窗口拉起 Python 服务（新电脑会自动安装依赖），并打开独立的管理窗口 `admin-portal.html`。
- **窗口唤醒**：运行期间再次双击，会唤醒并置顶已打开的窗口。
- **自动退出**：关闭管理窗口时，后台 Python 服务随之终止。

### 9.2 门户全局运维 (`admin-portal.html`)
- **🧹 清理垃圾**：调用 `janitor.py` 清理孤儿资源与幽灵记录。
- **Git 提交与云同步**：查看变更后一键推送（推送前自动执行只读测试门禁），或同步移动端变更。
- **加密设置**：配置主密码，用于加密私密文章与私密相册分类。

### 9.3 CMS 内容管理
- **新建**：点击 `+` 新建节点，后端在 `data/<module>/` 下创建同名 `.md`。
- **编辑**：CMS 内置**纯阅读器**。点击“外部编辑”后，用本地 Typora / Obsidian 打开正文，保存后切回窗口即自动热刷新；也可以通过源码抽屉快速查看源码。
- **排序与移动**：开启排序模式后，可以同级拖拽、拖入文件夹，或拖到面包屑移出目录。
- **标签**：`Tags` 抽屉支持 `AND` / `OR` / `DEL` 三种筛选模式，管理员可以重命名、删除、排序、批量移动分类，并清理闲置标签。

### 9.4 图库与相册
- **分类**：在 Album 后台增删分类，可对分类执行私密加锁。
- **上传**：在 Photos 后台拖入图片，自动生成原图、1600px AVIF 与 400px WebP。

### 9.5 空间与音乐
- **Space**：输入 URL 后自动抓取标题与图标。
- **Music**：输入 BV 号后自动拉取封面、标题与分 P 列表。

### 9.6 Markdown 内链
同模块内链、`[[双链]]` 与跨模块 `?openNote=` 的写法见 [AI开发指南 §6](AI开发指南.md#6-内部链接与跨模块跳转)。


## 10. 工程门禁与开发依赖

测试所需 Node / npm 工具、本地 Git hooks、自动版本号、GitHub Actions 与浏览器测试以[开发工具说明](../_studio/tooling/README.md)为准。套件 12 验证 AST 语法边界、暂存区版本隔离、Node 必需性及错误脱敏。路由、CMS、JSON 与存储入口使用 `services/contracts.py` 类型；内部异常经 `services/errors.py` 写入服务日志，对 API 返回稳定消息。


## 数据保障接口补充

| 方法与路径 | 行为 |
| :--- | :--- |
| `POST /api/photos/register` | 通用远端图片登记；`register_r2` 为兼容别名。 |
| `GET /api/admin/recovery` | 本机备份、回收批次和待同步数量。 |
| `POST /api/admin/backup` | 创建并校验完整备份，默认包含公私媒体。 |
| `POST /api/admin/verify_backup` | 校验指定备份，载荷 `{id}`。 |
| `POST /api/admin/restore_backup` | 先备份当前状态，再恢复指定备份，载荷 `{id}`。 |
| `POST /api/admin/restore_trash` | 无覆盖地恢复指定回收批次，载荷 `{id}`。 |
| `POST /api/media/retry` | 重试持久化媒体同步任务。 |
| `GET /api/crypto/rotation/export` | 导出 JSON 快照及逐文件版本。 |
| `GET /api/crypto/rotation/pending` | 查询待确认的私密媒体令牌撤销。 |
| `POST /api/crypto/rotation` | 校验版本与公开结构，统一提交所有重加密记录及新密钥环。 |
| `POST /api/crypto/rotation/finalize` | 确认当前数据密钥对应的媒体令牌已同步。 |

CMS 加锁载荷必须含 `sources: [{id, revision}]`，由前端对正文及结构计算；正文更新可带 `data.expectedRevision`，不匹配时拒绝覆盖。相册导出返回 `revision`，加锁必须回传 `expected_revision`，防止导出后的新增图片被旧密文遗漏。

本机状态、事务恢复、媒体配置与轮换协议见[数据保障与存储迁移](数据保障与存储迁移.md)。
