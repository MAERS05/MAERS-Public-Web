# 数据保障与存储迁移

本文说明本机管理端的数据恢复、备份、媒体存储切换与凭据撤销。适用范围为单用户、单标签页管理和线上静态展示。

## 1. 数据保障边界

- JSON、Markdown、媒体文件是持久化真源；SQLite 仅为可重建缓存。
- 正文读取失败不会转成空正文或错误提示写回。仅改标题不提交正文；正文保存与加锁校验读取版本，过时快照会被拒绝。
- 阅读器保留 Vditor 的默认 HTML 净化；引擎缺失时以纯文本显示 Markdown，防止降级路径执行文章中的 HTML 事件或危险链接。
- 缺少必要索引、正文或配置时中止垃圾清理。清理候选移入本机回收区，不因本地缺图删除图库记录。
- 文件事务在修改真源前将原文件和校验信息持久化。进程中断后，启动、数据读取及后续写入会先恢复；恢复失败时保留日志并停止相关操作。
- 媒体上传、删除和私密迁移共用写锁。同步失败保留待办，并显示“本机已保存、云端待同步”；未完成待办会阻断发布。
- 加锁私有副本按 SHA-256 验证内容，不能只凭对象存在就删除唯一源。公私迁移的补偿计划在远端写入之前落盘。

本机状态位于 `_studio/.local/`，不纳入 Git。管理服务器按请求路径和最终目标路径禁止直接下载 `_studio/`、媒体凭据及隐藏文件，并覆盖 Windows 大小写、尾点/空格及数据流别名。不要把整个本机工作目录原样上传到静态托管；线上部署须运行 `node _studio/tooling/build-site.mjs` 并仅发布 `dist/`，Vercel 已在 `vercel.json` 配置此流程。独立同步工具与管理服务使用进程锁互斥，运行工具前应关闭管理端。

## 2. 备份与恢复

后台门户提供“备份与恢复”入口：

1. **创建完整备份**：保存当前本地数据、Markdown、标签、被包裹的密钥环和媒体后端公私两侧的全部 `photos/` 对象。生成逐文件校验清单并核验后才显示完成。
2. **校验**：重新检查所有备份文件的大小及 SHA-256。备份缺失或损坏时禁止恢复。
3. **恢复备份**：先备份当前状态；恢复所选文件，备份之后新增的本地文件移入回收区。远端恢复包含持久化补偿，失败或进程终止后可以恢复到操作前状态。
4. **恢复回收区**：按整理批次还原。目标路径已有新文件时停止整批恢复，避免覆盖。
5. **重试图片同步**：重新执行持久化媒体待办。若存储配置已经变更，应先恢复原配置并完成待办。

备份在 `_studio/.local/backups/<编号>/`，回收区在 `_studio/.local/trash/<编号>/`。每份目录包含 `manifest.json` 和按清单索引的文件块；移动备份时必须复制整份目录。

本机备份不是独立磁盘备份。应将完整备份目录复制到另一块磁盘，并保管恢复码及媒体存储配置。备份可能包含公开原文、历史明文和私密图片，需要保护其访问权限。主密码不发送给后端，数据密钥只允许留在浏览器与已验证的本机服务内存，不进入备份。

## 3. 存储配置与替换

后端优先读取 `_studio/tools/media_config.json`，不存在时兼容原有 `r2_config.json`。没有配置文件时使用本机目录后端；配置损坏或凭据缺失不会静默回退到其他存储。

### S3 兼容存储

```json
{
  "provider": "s3",
  "endpoint_url": "https://storage.example.com",
  "region": "auto",
  "access_key_id": "填写访问密钥",
  "secret_access_key": "填写私密密钥",
  "public_bucket_name": "public-media",
  "private_bucket_name": "private-media"
}
```

现有 R2 的 `account_id`、`bucket_name` 等字段继续有效，endpoint 可由 account_id 推导。更换凭据不会改变数据键；更换实际 endpoint 或桶名则视为更换存储目标，未完成恢复日志不能对新目标执行补偿。

相册加密迁移需要凭据具有公开桶、私有桶两侧的**对象读写**权限，仅授权公开桶会导致私有迁移返回 403。请将凭据范围限定为这两个媒体桶；不要开放私有桶的公开访问来解决权限问题。程序会在启动迁移前检查私有对象读取权限，上传、读取或删除被拒绝时明确提示对应存储侧，保留尚未删除的源文件。R2 凭据保存在本机 `_studio/tools/r2_config.json`（或优先读取的 `media_config.json`），更新后重新发起操作即可。

### 本机目录后端

```json
{
  "provider": "local",
  "root": "_studio/.local/media"
}
```

目录下分别保存 `public/` 和 `private/` 对象，业务继续使用 `photos/images/...` 等逻辑键。该后端可用于本机独立运行、测试及后续存储适配。

本机目录不等于线上图片已经发布。若公开图片改为随静态站点发布，需要把公开对象纳入部署产物；原图当前被 `.gitignore` 排除，应在确认迁移方案后调整。私密对象不能放入公开产物，线上访问仍需要私有媒体网关。当前未实现“私密图片密文随静态站点发布、浏览器解密”的模式。

### 前端与手机上传

- `custom/config.js` 中的 `MEDIA_PUBLIC_BASE` 是公开原图入口，留空表示使用站内相对路径。缩略图、预览图继续优先使用索引中的真实路径，私密带令牌 URL 不经公开入口改写。
- `data/crypto-keyring.json` 的 `media_base` 是私密媒体读取网关，独立于公开原图地址。
- 手机中继 Worker 保留 R2 绑定，同时支持 `MEDIA_GATEWAY_URL`、`MEDIA_GATEWAY_TOKEN` 和 `MEDIA_PUBLIC_BASE`，可接入独立 HTTPS 文件服务。
- HTTPS 网关接收 `Authorization: Bearer <MEDIA_GATEWAY_TOKEN>`，提供 `GET/HEAD/PUT /objects/public/<文件键>` 与 `/objects/private/<文件键>`；私有侧还须支持 `_maers/private-token.json`。必须保证写入后读取当前对象、鉴权、内容类型和无缓存令牌读取。
- 电脑图片登记使用通用 `/api/photos/register`；旧 `/api/photos/register_r2` 保留为兼容别名。

迁移顺序：完成旧存储待办和事务恢复 → 完整备份 → 复制公私对象且保持逻辑键 → 比较数量、大小及 SHA-256 → 使用新配置验证公开与解锁访问 → 观察确认后再停用旧存储。本次代码调整没有迁移或删除真实云端图片。

## 4. 密码修改与凭据撤销

**日常修改主密码、重新生成恢复码**只更新当前密钥环的包裹槽，不更换数据密钥。拿到旧密钥环和旧密码/恢复码的人仍可能获得旧数据密钥；不能将这种修改描述为撤销所有历史凭据。

后台加密设置新增**“更换数据密钥并撤销旧凭据”**：

1. 在浏览器验证当前主密码，生成新的随机数据密钥、新主密码槽和新恢复码。
2. 递归重加密全部 JSON 记录，包括加密文件夹内的嵌套密文，并逐条解密验证结果。
3. 用户确认保存新恢复码后，后端校验所有真源版本，创建本机备份，通过一个可恢复事务统一提交全部密文与新密钥环。
4. 将新媒体令牌摘要同步至私密存储，并读取确认后完成本机撤销回执。失败时保留新密文及新密钥环，标记“令牌撤销待完成”，禁止发布；重新打开设置、用新密码解锁后重试“同步令牌”即可继续。

Worker 对新令牌使用私有存储对象读取，不保留旧令牌的内存缓存；KV 仅作为旧配置首次迁移的兼容读取。`PRIVATE_TOKEN_HASH` 环境变量仍有优先级，若它覆盖新值，界面会要求移除或更新，不能误报撤销成功。必须部署新版 Worker，才能获得这项行为。

所有记录重加密前必须能被旧密钥正常解密；任何一条损坏或任何真源发生变化都会停止整批提交。没有加密内容时也可以更新数据密钥；存在加密内容时，后端拒绝直接强制替换为另一把密钥。

已经被复制的旧密文、旧明文、Git 历史或备份无法远程收回。完整轮换保护新版本的记录，不能改变对方已持有的旧副本。

## 5. 隐私功能说明

- 文章正文、文章及相册等记录的元数据使用 AES-GCM 加密；本机编辑复用相同的加密实现，线上访客在浏览器内解密。
- 私密图片当前采用私有存储与令牌鉴权，文件字节不是浏览器端到端加密；存储服务仍可读取图片。
- 首页卡片加锁只保护导航记录并提供页面显示守卫，不自动加密目标页面的 JSON、正文或图片。私密内容应在文章或相册层单独加锁。公开图片上传成功时即已能被直接访问；如果图片从一开始就不应公开，应使用私有上传通道，不能依赖先上传公开桶再加锁来撤回此前的暴露。

## 后台管理与对外加密

加密决定前台发布状态，不再把本地后台的内容替换为锁定占位。有加密记录时，后台启动验证一次主密码；随后可以编辑正文、修改标题和标签、排序、上传图片。每次保存直接重新封装密文，不生成第二套长期保存的明文原件，也不把私密正文放进 SQLite 缓存。

数据密钥仅通过带本机令牌的回环接口交给服务内存；加密桥通过标准输入调用已有 Node.js Web Crypto 实现，不写密钥文件或命令行参数。需要项目原有 Node.js 环境。正常离开页面会请求关闭该页的管理状态，下一后台页可用当前标签页已有密钥重新建立；“退出私密管理”同时清除标签页密钥。浏览器异常终止时关闭请求不保证送达，应退出本机管理服务以释放其内存。浏览器或系统的交换文件、崩溃转储不在应用的持久化保证范围内。

加密相册和文章的新原图、缩略图、预览图在内存处理后直接写入私有存储，全部核验后才更新加密索引。取消图片引用保留私有对象，供备份和恢复使用；取消对外加密才把仍引用的图片恢复到公开侧。私密文章“编辑”打开浏览器源码抽屉，不唤醒需要物理明文文件的外部编辑器。

“取消加密 / 取消全部加密”意味着恢复公开；与后台日常编辑是两种操作。本机私密写入验证失败时直接停止，不能降级为公开上传或把明文排入云端中继。访客阅读仅在浏览器内存中解密，不改变已发布文件。
- 私密文章标题不写入长期阅读历史；加载历史时清除旧版本残留的不可访问或私密条目。

## 6. 实现与验证入口

- [storage.py](../_studio/services/storage.py)、[storage_journal.py](../_studio/services/storage_journal.py)：写锁、原子文件操作、持久化事务与重启恢复。
- [media_store.py](../_studio/services/media_store.py)、[media_jobs.py](../_studio/services/media_jobs.py)：存储适配、内容校验与同步待办。
- [data_safety.py](../_studio/services/data_safety.py)：清理预检、回收区、完整备份与校验恢复。
- [crypto_rotation.py](../_studio/services/crypto_rotation.py)、[key-rotation.module.js](../data-manage/encrypt/key-rotation.module.js)：整体密钥轮换与令牌确认。
- [test_13_data_safety.py](../_studio/tests/test_13_data_safety.py)：隔离故障恢复与存储替换回归。

历史入口 `python -B _studio/tools/upload_to_r2.py` 现在使用统一存储配置，只同步公开索引中的原图；可选 `--backup`、`--verify <编号>`、`--restore <编号>`、`--retry`。

全量测试命令为 `python -B _studio/tests/run_tests.py`。发布门禁会拒绝未恢复事务、未完成媒体待办和未确认的令牌轮换；HTTP 测试还验证私有本机状态不可直接下载。浏览器测试使用临时数据，不连接真实图片桶。

本地回归覆盖已实现的核心流程、安全边界与故障恢复，不代表整套线上工作流已经验收。真实媒体存储、部署后的 Worker、手机云同步、完整离线下载与断网浏览、桌面启动器及外部编辑器仍需在对应环境单独验收。

## 公开密钥环与本机恢复材料

`data/crypto-keyring.json` 仅发布 `v`、`dek_id`、`pw`（salt/iter/wrap）、`media_base`。完整密钥环的恢复码包裹槽与更新时间保存在 `_studio/.local/crypto-keyring.json`，通过已鉴权的本机 `/api/crypto/keyring` 读取，不作为静态文件下载。迁移、保存和密钥轮换使用同一多文件事务，失败回滚；旧备份恢复后自动再次分离。完整备份包含这份本机密钥环，换机不可只依赖 Git 克隆。

发布产物排除后台 HTML、后台主入口、加密设置/密钥轮换界面代码、Worker 源文件、Python 服务和本机目录；访客端仍依赖部分共享管理模块，不能按文件夹名称一概删除。取图地址仍需提供给浏览器；本次不更换密码、数据密钥或图片令牌。历史 Git 提交和旧 Vercel 部署中的文件不会被新发布自动撤回。
