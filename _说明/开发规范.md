## 0. 执行等级与检查方式

| 标记 | 含义 | 失败后果 |
| :--- | :--- | :--- |
| ✅ 硬性 | 由自动化测试强制，**零容忍** | 测试失败，Git 推送被门禁拦截 |
| 🟡 棘轮 | 由自动化测试强制，存量欠账登记在基线中，**只减不增** | 新增违规或欠账增长时测试失败 |
| 👁 审查 | 无法可靠静态检测，依靠代码审查与 AI 自检 | 审查不通过即返工 |

```bash
python -B _studio/tests/run_tests.py            # 全量测试（提交前必跑）
python -B _studio/tests/run_tests.py --fast     # 只读契约与规范守卫（= 推送前门禁）
python -B _studio/tests/run_tests.py -k standards  # 只运行规范守卫套件
python -B _studio/tests/run_tests.py --debt     # 查看技术债台账
python -B _studio/tests/run_tests.py --shrink-baseline  # 偿还欠账后收缩基线
```

- 规范扫描器位于 [`_studio/tests/standards.py`](../_studio/tests/standards.py)，守卫套件是 [`test_09_code_standards.py`](../_studio/tests/test_09_code_standards.py)。
- 规则编号（`STD-xxx-nn`）在扫描器、测试失败信息与本文之间一一对应。测试 `test_05_rules_documented` 会检查每条自动化规则是否都在本文登记。

## 1. 文件与目录 (FILE)

| 编号 | 等级 | 规则 |
| :--- | :--- | :--- |
| STD-FILE-01 | ✅ | 前端资源（`custom/` `shared/` `data-manage/` `static-style/` `ui/` 与根目录 HTML）使用**小写 kebab-case**：`cms-tags-drawer.module.js`、`mobile-photos.css`。Python 模块使用 **snake_case**：`cms_other_tags.py`。 |
| STD-FILE-02 | ✅ | ES 模块必须以 `.module.js` 结尾。经典脚本例外须登记在 `NON_MODULE_JS_ALLOWLIST`，并写明理由。目前只有 `custom/config.js`、`shared/flash-guard.js`、`custom/index/viewer/site-guide.js`、`custom/zmobile adaptation/mobile-literature.js`、`custom/zmobile adaptation/mobile-photos.js`、`custom/zmobile localization/offline-download.js`、`data-manage/sync/cloudflare-worker-sync.js`。 |
| STD-FILE-03 | ✅ | 项目根目录只允许页面 `.html`，以及登记的配置文件：`README.md`、`LICENSE`、`manifest.json`、`vercel.json`、`maers-version-controller.js`、`Maersy.exe`、`.gitignore`、`.gitattributes`。 |
| STD-FILE-04 | ✅ | `custom/<module>/` 根部只放入口 `main.module.js` / `admin-main.module.js` 与 `*-adapter.module.js`，其余文件必须位于 `viewer/` 或 `admin/` 子树。`custom/` 根部只允许 `config.js`。移动端目录 `zmobile adaptation/` 与 `zmobile localization/` 不受此约束。 |
| STD-FILE-05 | ✅ | `_studio/` 根部只允许 `config.py`、`routes.py`、`server.py`、`requirements.txt`。禁止 `.bat` / `.cmd` / `.ps1` / `.sh` 脚本。每个 `_studio/tests/test_*.py` 都必须注册到 `tests/__init__.py` 的 `SUITES`。 |
| STD-FILE-06 | 👁 | 新建文件前先查阅 [文件功能说明](文件功能说明.md)，优先扩展已有模块。只有职责明确独立时才拆分新文件，禁止为单个函数新建文件。 |

### 1.1 新文件放在哪里

| 文件职责 | 位置 |
| :--- | :--- |
| 业务模块访客端逻辑 / 样式 | `custom/<module>/viewer/` |
| 业务模块管理端逻辑 / 样式 | `custom/<module>/admin/` |
| 跨模块共享 UI 基础设施（主题、布局、工具、Toast） | `shared/` |
| 管理中台通用组件（保存条、弹窗、批量管理） | `data-manage/admin/` |
| 加密与私密媒体（唯一允许触达 `crypto.subtle` 的位置） | `data-manage/encrypt/` |
| 云同步（GitHub / Cloudflare / Git 提交） | `data-manage/sync/` |
| 移动端 `@media` 补丁 | `custom/zmobile adaptation/mobile-<module>.css` |
| 全局样式 / 主题令牌 | `static-style/` |
| SVG 图标 | `ui/` |
| 后端业务服务 | `_studio/services/<domain>.py` |
| 后端独立 CLI / 构建工具 | `_studio/tools/` |
| 自动化测试 | `_studio/tests/test_NN_<topic>.py` |
| 内容数据 / 快照 / 标签配置 | `data/`、`data/<module>/*.md`、`data/tags/` |

## 2. JavaScript (JS)

| 编号 | 等级 | 规则 |
| :--- | :--- | :--- |
| STD-JS-01 | ✅ | 禁止提交 `debugger`。 |
| STD-JS-02 | ✅ | 禁止 `var`，统一使用 `const` / `let`。 |
| STD-JS-03 | ✅ | 禁止提交 `console.log`。保留的诊断信息使用 `console.warn` / `console.error`（带 `[MAERS]` 等前缀），一次性调试输出必须删除。 |
| STD-JS-04 | ✅ | 禁止 `alert()`。用户反馈统一走 `window.MAERS.Toast`；需要确认时使用 `data-manage/admin/admin-modal.module.js`。 |
| STD-JS-05 | ✅ | 每个 JS 文件以 `/** ... */` 文档注释开头，用中文写明模块名称与职责。 |
| STD-JS-06 | ✅ | 单个 JS 文件不超过 **800** 行。超过时按职责拆分为子模块（参考 `cms-tags-*`、`theme-*` 的拆分方式）。 |
| STD-JS-07 | ✅ | 禁止在 `custom/config.js` 以外硬编码 `localhost:端口` / `127.0.0.1:端口`。API 地址统一读取 `window.MAERS.Config.API_BASE`。 |
| STD-JS-08 | 👁 | 所有注释使用中文。禁止保留僵尸代码、注释掉的旧实现与“保留旧逻辑再覆盖”的写法。 |
| STD-JS-09 | 👁 | 用 `innerHTML` 拼接动态数据前，必须先经过 `Utils.escapeHtml()`。纯文本优先使用 `textContent`。 |
| STD-JS-10 | 👁 | 异步统一使用 `async/await`。不要用 `setInterval` 轮询状态，优先用事件回调或订阅。 |
| STD-JS-12 | 👁 | 新增图标优先复用 `ui/` 资源；整理 SVG 与内联样式时必须保持现有图形、尺寸、配色、布局及交互外观一致。存量内联 SVG 由 `--a11y` 只读列出，迁移前逐项核对。 |
| STD-JS-11 | 👁 | 模块依赖通过 `import` 显式声明，或通过 `init(deps)` 注入。禁止模块之间通过全局变量隐式通信。 |

| :--- | :--- | :--- | :--- |

## 4. CSS 与主题 (CSS)

| 编号 | 等级 | 规则 |
| :--- | :--- | :--- |
| STD-CSS-01 | ✅ | `@media` 查询必须放在 `custom/zmobile adaptation/` 中，并由主 CSS 顶部 `@import` 引入。唯一例外是全局响应式表 `static-style/responsive.css`。 |

| 编号 | 等级 | 规则 | 检查 |
| :--- | :--- | :--- | :--- |
| STD-HTML-01 | ✅ | 每个页面必须在 `<head>` 中同步引入 `shared/flash-guard.js`，禁止加 `defer` / `async` / `type="module"`。 | test_01 |
| STD-HTML-02 | ✅ | 页面引用的本地 `script` / `link` / `img` 资源必须真实存在。内联脚本禁止从远程 CDN 加载 ES 模块。 | test_01 |
| STD-HTML-03 | 👁 | `<head>` 顺序依次为：`custom/config.js`、`shared/flash-guard.js`、全局样式表、业务入口 `<script type="module">`。每个页面只引入一个主入口模块。 | — |
| STD-HTML-04 | 👁 | 图片列表统一使用 `<img loading="lazy">` 配合 `object-fit: cover`，禁止 `background-image` 方案与手写 `IntersectionObserver`。 | test_04（核心网格） |
| STD-HTML-05 | 👁 | 页面声明语言，提供主内容地标与标题；图片声明替代文本，表单具有明确名称。通过静态审计与浏览器 axe 列出问题。 | `--a11y` / axe 审计 |

| STD-HTML-07 | 👁 | 以普通文字 4.5:1、大文字 3:1 为对比度审查标准，检查深浅色、焦点可见性与减少动态效果设置。检测只报告问题；涉及既有配色、字体、位置或控件外观的调整必须先取得用户明确授权。 | axe / 人工审查 |

## 6. Python 后端 (PY)

| 编号 | 等级 | 规则 |
| :--- | :--- | :--- |
| STD-PY-01 | ✅ | 每个 Python 模块以模块级 docstring 开头，用中文写明职责。 |
| STD-PY-02 | ✅ | 禁止裸 `except:`，至少捕获 `Exception`，能确定类型时捕获具体异常。 |
| STD-PY-03 | ✅ | 业务服务（不含 `tools/`、`tests/`）的日志统一使用 Studio Engine 双语格式：`print(f"  [ MODULE ] 图标 中文描述 \| English description")`，其中 `MODULE` 为大写模块标签。 |
| STD-PY-04 | ✅ | 单个业务 Python 模块不超过 **700** 行，超过时按职责拆分到 `services/<domain>_<sub>.py`。 |
| STD-PY-05 | 👁 | 只使用标准库，加上 `server.py` 中 `ensure_dependencies()` 管理的依赖（Pillow、pillow-avif-plugin、boto3）。直接及传递依赖的版本统一锁定在 `_studio/requirements.txt`；新增或升级依赖须同步锁文件、自检列表并运行全量测试。 |
| STD-PY-06 | 👁 | 路由层只负责参数解析与状态码映射，业务逻辑放在 `services/`。状态码约定：参数错误 `400`、资源不存在 `404`、未知接口 `404`、内部异常 `500`。 |
| STD-PY-08 | 👁 | 路由、JSON 与存储边界使用 `services/contracts.py` 的载荷及响应类型；确定异常类型时精确捕获，最外层 HTTP、后台任务及外部 SDK 的兜底异常必须记录日志并返回稳定的公开错误，不透传内部异常文本。 |
| STD-PY-07 | 👁 | 写入 JSON 等关键文件时使用“临时文件 + `os.replace`”原子替换（参考 `crypto_keyring.py`）。用户可控的文件名必须拒绝 `..`、`/`、`\`。 |

## 7. 数据与 API (DATA)

| 编号 | 等级 | 规则 | 检查 |
| :--- | :--- | :--- | :--- |
| STD-DATA-01 | ✅ | `data/` 下所有 JSON 必须是合法的 UTF-8 JSON。CMS 快照结构为 `{"root": [...]}`，节点 `id` 全局唯一，未加密节点的 `.md` 文件必须存在。 | test_03 |

| STD-DATA-04 | 👁 | 主密码只在浏览器使用，主密码与明文数据密钥不得由应用写入文件、日志、命令行参数或云端。持久化仅保存包裹后的密钥：完整密钥环在 `_studio/.local/crypto-keyring.json` 并纳入完整备份，`data/crypto-keyring.json` 只保存公开解锁字段；本地后台可经已鉴权的回环接口把数据密钥交给本机服务内存，用于无明文副本的管理，退出或服务结束时清除。 | test_03 / test_07 / test_13 |

## 11. 标准工作流清单

### 11.1 新增前端模块

1. 按 [1.1](#11-新文件放在哪里) 确定目录，文件名使用 kebab-case + `.module.js`。
2. 文件头写 `/** */` 职责注释（STD-JS-05），并通过 `import` 显式依赖。
3. 样式使用主题变量，同时适配浅色模式。移动端样式写入 `zmobile adaptation/` 并在主 CSS 顶部 `@import`。
4. 如果模块不在任何 `groups` 前缀内，在 `maers-version-controller.js` 中新增分组。
5. 访客端文件加入 `offline-download.js` 的 `FRAMEWORK`。
6. 更新 [文件功能说明](文件功能说明.md)。

### 11.2 新增后端接口

1. 业务逻辑写在 `_studio/services/<domain>.py`（模块 docstring + 双语日志）。
2. 在 `routes.py` 用 `@route` 注册接口和统一校验器；分发器集中处理锁与状态码，业务写入交给服务层。
3. 在对应沙盒套件（05–07）中补充用例。
4. 更新 [后端开发指南 §4](后端开发指南.md#4-api-路由规范) 的接口表。

### 11.3 新增测试套件

## 12. 棘轮基线（技术债台账）

原有五类欠账已清零并升级为硬性规则。空基线仅保留历史治理机制，不能用它放宽现有规则。

- 基线文件为 [`_studio/tests/standards_baseline.json`](../_studio/tests/standards_baseline.json)，按规则编号记录 `{文件: 违规数}`。体量规则记录的是行数。
- **新增文件必须完全合规**：基线外的文件只要出现违规，测试就会失败。
- **既有欠账禁止增长**：计数超过基线时测试失败。体量规则允许 30 行浮动，避免小修复被阻断。
- **偿还即锁定**：某个文件的计数下降后，`test_03_ratchet_baseline_shrunk` 会要求执行 `--shrink-baseline`，防止已偿还的债务被悄悄回退。
- 禁止手工向基线新增条目。规则清零后，应从 `RATCHET_RULES` 移到 `HARD_RULES`。
- 使用 `--debt` 查看当前台账，优先偿还体量最大的文件。

## 13. 新增或调整一条规则

4. 运行全量测试，确认没有误报。
